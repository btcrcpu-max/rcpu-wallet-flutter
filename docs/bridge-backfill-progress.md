## 2. 逐项详细待确认内容（含回填格式）

### 2.1 B1 赎回方法形态（P0）

- 待确认：最终采用 `redeem(uint256,string)` 合约方法还是 `burn` + 链下登记；
- 需要桥侧给出：**方法签名 + ABI 片段**（`abi_fragment`）；`rcpuAddress` 参数约束（必须仅明文 `rcpu1`？长度/校验规则）；
- 回填字段：`method` / `signature` / `abi_fragment` / `notes`。

### 2.2 B2 estimatedMinutes 口径（P1）

- 待确认：静态固定值还是动态计算；单位；上限；`null` 语义；
- 回填字段：`type`（static/dynamic）/ `range` / `cap` / `notes`。

### 2.3 B3 专属存款地址生成规则（P0）

- 待确认：生成算法（是否确定性）；同一 BSC 地址是否永久绑定同一地址；是否可预测/需要服务端签名背书；
- 回填字段：`generation` / `algorithm` / `binding` / `notes`。

### 2.4 B4 到账通知机制（P2）

- 待确认：是否提供 Webhook / WebSocket / 事件回调及字段定义；不提供则维持轮询；
- 回填字段：`notification` / `webhook` / `websocket` / `notes`。

### 2.5 B5 幂等键实现（P1）

- 待确认：幂等键存储时长；重复提交返回码（目标 `alreadyRecorded=true` + 200 或 409）；客户端重试策略；
- 回填字段：`idempotency_ttl_hours` / `conflict_code` / `conflict_message` / `dedup_key` / `notes`。

> 回填示例 JSON 见 `docs/bridge-backfill-schema.md` §1；桥侧可直接按该结构回复。

- 桥侧若回复与草案差异大（如 B3 改为随机地址而非确定性映射），需同步修订
  `fetchDepositAddress` 幂等假设与 `bridge-api-contract-c4.md`，必要时追加安全评审；

  客户端轮询与状态机需对应调整（影响 UI 文案与 TC-REDEEM 系列断言）。
